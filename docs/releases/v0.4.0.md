# v0.4.0 — Web Foundation and Dashboard

The explorer now has its first modern website: a server-rendered dashboard that
reads the existing native Ryo API, with readable block/transaction pages, public
height/hash search, a developer guide and additional JSON/raw views.
The old website and templates remain excluded.

## Added

- Next.js, TypeScript, Tailwind and shadcn/ui foundation with bundled fonts/icons,
  persistent light/dark themes and responsive keyboard-accessible navigation.
- Official Ryo logos, a horizontal header and the official website's day/night
  palette, with locally bundled Inter/Montserrat typography.
- Native-reader chain status, exact tip height/difficulty, estimated hashrate,
  issued supply including the native dev fund, latest coinbase payout,
  last-100 median size, confirmed ordinary count and local pool count/size.
  Recent blocks retain anchored earlier-block navigation with reorg recovery.
- Optional public node status with synchronization progress, peer count,
  next-block difficulty/hashrate and observation time. Delayed reads are marked.
  Independent live health checks show recent native sync errors with expandable
  safe details and distinguish an observed stall from a verification failure.
- Full-width paired block/confirmed-transaction tables on desktop, stacking on
  mobile; the bounded native TX preview includes coinbase, exact fees and links
  to HTML details and refreshes with the live reader. Native size, input/output
  counts and exact fee/KiB appear when available from the bounded summaries.
- Ten-second live tip checks on the latest dashboard, with pause, hidden-tab
  suspension, bounded reads, last-check time/height and automatic updates
  preserving browser state; pool count/size changes also refresh the overview.
- A block-interval bar chart with numbered block/seconds axes, 1h/24h/7d/30d
  controls and accessible inspection. The hour view labels every block, follows
  the latest bar at the right edge. A fixed-size responsive plot fits every
  returned bar in view and shows the exact native count.
  Inspection holds the graph during sync; a top-right "Back to live" button
  resumes following, with no scrollbar or range input. An additive bounded
  native timestamp route
  supplies actual historical windows; signed differences remain intact and
  periods end at the explicitly dated latest available block during sync.
- Readable block headers and paginated transaction lists, with links to native
  transaction details, exact fees, inclusion state, public outputs and ring
  candidate metadata. Hidden output amounts remain explicitly unavailable.
- Global search by block height, block hash or transaction hash, using the
  existing native API rather than a separate index. A sticky menu receives the
  search only after scrolling past its page location, preserving draft and focus.
- Formatted JSON/raw views inside the explorer layout, with exact token
  preservation, original-view toggle and verbatim downloads.
- A dedicated paginated mempool with native fees/size/input/output/ring/payment-ID
  summaries, membership-aware live updates, pause and mutation recovery. An
  owner-requested node-local receive timestamp shows UTC time/age with a tooltip
  distinguishing it from creation, confirmation and other nodes' observations.
- Native public inspection tools for confirmed key-image status, transaction
  output-key membership and public-address format/network validation, linked
  from transaction details and with embedded JSON results.
- A same-origin bounded read-only adapter and a developer API guide.
- Precision/resource tests, production browser accessibility checks and a
  production frontend smoke against native genesis and a limited real mainnet
  sync, including automatic dashboard updates and real spend-transaction pages.

## Changed

- Product metadata advances to 0.4.0; existing API v2 shapes and the supported
  legacy API fields remain unchanged. The block-interval route and optional
  network `overview`, transaction `inspection`, mempool and public tool routes
  are added; closed-schema clients must update their
  contract.
  Native Ryo crypto and LMDB stay authoritative.
- The full native GitHub Action remains manual-only. No new per-PR or per-merge
  frontend build Action is introduced.

## Fixed

- Native point-identity comparison now uses existing field helpers rather than
  raw limbs and rejects invalid zero projective coordinates. The pinned core
  build applies a separate reviewed patch, with old/new regression evidence,
  public boundary fixtures and native proof rejection checks.

## Upgrade Notes

Rebuild the pinned core with `scripts/build-ryo-core.sh` to apply both reviewed
patches, then rebuild the daemon and explorer and restart them using the existing
database. A compatibility-only SDK is migrated by the guarded helper; unrelated
tracked/staged SDK changes are refused. See [build setup](../BUILD.md).
Rebuild the native server and enable `--enable-api-v2`.
Install Node.js 24 LTS, then run `npm ci`, `npm run build` and `npm run start` in
`web/`. Set the server-only `RYO_API_URL` to the native API origin; it defaults to
`http://127.0.0.1:8081`. Keep `--enable-json-api` if legacy clients need that subset.
Optionally configure the private server-only `RYO_DAEMON_RPC_URL` for node status.
Enable bounded error details with the same daemon's `RYO_DAEMON_LOG_PATH` and
`RYO_DAEMON_LOG_UTC_OFFSET`; see the operation guide for exact scope.
The website is a separately run Node process; no external database or Docker is
required. See [web operation](../WEB.md) for commands, bounds and deployment scope.

## Known Issues

- Address balance/history search, wallet-export/private-key verification, SSE
  and advanced analytics remain later milestones. Detail input/extra previews have documented display
  bounds; full public DTO and raw responses remain separately available.
- Reader chain data does not establish network-wide synchronization. Independent
  requests can see different heights. Optional status reports this node's target;
  it is checked on page refresh and may retain a marked observation for up to
  60 seconds after failure. Chart timestamps are miner supplied.
- Native semantic rejections recurred at heights 230,110 and 238,751; fresh
  replay accepts the public bytes. A reproducible point-identity defect was
  corrected and the rebuilt daemon resumed from the existing database. Direct
  attribution of the intermittent runtime failures remains unproven, as does
  full current-tip parity. See the validation and diagnostic reports.
- Full-chain capacity, live LMDB mapping growth, external-writer stress, wider
  historical coverage and positive testnet/stagenet fixtures remain unverified.
- Production dependencies have no reported advisories in the recorded audit.
  The developer-only Next ESLint glob dependency includes the unpatched `braces`
  advisory GHSA-vfj7-8cjw-p6xm; no visitor-supplied glob pattern reaches it. See
  the validation report for the exact audit scope.

No public website deployment or packaged binary distribution is included.
